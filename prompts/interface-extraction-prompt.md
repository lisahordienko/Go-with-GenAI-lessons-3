## Мій промпт

Ти — досвідчений Go-розробник. Рефакторизуй код у стилі чистої архітектури: мінімальні інтерфейси, dependency injection і тестованість без реальної БД.

Контекст: `OrderService` зараз напряму залежить від `*sql.DB` і викликає `Exec(...)` всередині `PlaceOrder`. Виділи абстракцію для того, що сервіс реально використовує.

Завдання:
1. Створи мінімальний інтерфейс `OrderStore` для `OrderService`.
2. Перепиши `OrderService` так, щоб він отримував залежність через конструктор: `NewOrderService(store OrderStore) *OrderService`.
3. Збережи `PlaceOrder(orderID string, amount float64) error` і викликай `store.Exec(...)` з правильним SQL і аргументами.
4. Згенеруй простий мок для тестів без реальної БД.

Обмеження:
- Інтерфейс має бути маленьким і точним: лише потрібні методи, без зайвих.
- Не змінюй логіку домену, якщо вона вже правильна.
- Пиши ідіоматичний Go, без зайвих абстракцій і без глобальних змінних.
- Мок має дозволяти перевіряти виклик `Exec` і повертати помилку при необхідності.

Вивід: поверни лише чистий Go-код у трьох частинах у такому порядку:
1. `type OrderStore interface { ... }`
2. `type OrderService struct { ... }`, `NewOrderService(...)` і `PlaceOrder(...)`
3. мок-тип для тестів з реалізацією `Exec(...)`

Не додавай пояснення, Markdown, коментарі типу "ось що я зробив". Тільки Go-код, готовий до вставки в проект.
